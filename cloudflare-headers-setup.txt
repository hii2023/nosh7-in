=== CLOUDFLARE SETUP INSTRUCTIONS ===
(Save this file — these are manual steps to do in Cloudflare dashboard)

--------------------------------------------------
PART 1: SECURITY HEADERS
--------------------------------------------------

Go to: Cloudflare Dashboard → nosh7.in → Rules → Transform Rules → Modify Response Headers

Click "Create rule" and name it: Security Headers

Set the condition:
- When: Hostname → equals → nosh7.in

Set the action (add each one as a "Set" header):
  Header Name                    Value
  ───────────────────────────────────────────────────────────────────
  Strict-Transport-Security      max-age=31536000; includeSubDomains
  X-Frame-Options                SAMEORIGIN
  X-Content-Type-Options         nosniff
  Referrer-Policy                strict-origin-when-cross-origin
  Permissions-Policy             geolocation=(), microphone=(), camera=()

Click Save.

--------------------------------------------------
PART 2: HTTP TO HTTPS REDIRECT RULE
--------------------------------------------------

Go to: Cloudflare Dashboard → nosh7.in → Rules → Redirect Rules

Click "Create rule" and name it: HTTP to HTTPS

Set the condition:
- When: http.scheme → equals → "http"

Set the action:
- Redirect to: https://${http.host}${http.request.uri.path}
- Type: 301 Permanent

Click Save.

--------------------------------------------------
PART 3: SSL SETTINGS (if not already done)
--------------------------------------------------

Go to: Cloudflare Dashboard → nosh7.in → SSL/TLS → Overview
- Set SSL mode to: Full (strict)

Go to: SSL/TLS → Edge Certificates
- Enable: Always Use HTTPS (toggle ON)
- Enable: HSTS (optional, advanced)

--------------------------------------------------
NOTE: GitHub Pages already gives you HTTPS automatically.
The above Cloudflare rules add extra security headers on top.
You only need Part 1 once Cloudflare is connected as your proxy.
--------------------------------------------------

--------------------------------------------------
PART 4: STATIC ASSET CACHING (PageSpeed "Efficient cache lifetimes")
--------------------------------------------------
Why: GitHub Pages serves assets with only Cache-Control: max-age=600 (10 min),
so returning visitors re-download JS/CSS/images. The _headers file in this repo
is IGNORED by GitHub Pages, so the cache lifetime must be set at Cloudflare.
Safe to set a 1-year immutable TTL because every asset URL carries a ?v= query
string that we bump whenever the file changes (assets/*.js, *.css, *.webp, etc).

Go to: Cloudflare Dashboard -> nosh7.in -> Caching -> Cache Rules -> Create rule
Name it: Long-cache static assets

When incoming requests match (edit expression):
  (starts_with(http.request.uri.path, "/assets/")) or
  (starts_with(http.request.uri.path, "/js/")) or
  (http.request.uri.path.extension in {"webp" "png" "jpg" "jpeg" "svg" "gif" "ico" "css" "js" "woff" "woff2"})

Then, under "Cache eligibility":
  - Eligible for cache: ON  (Cache status: Eligible for cache)
  - Edge TTL: Override origin -> 1 year (31536000 seconds)
  - Browser TTL: Override origin -> 1 year (31536000 seconds)

Click Deploy.

IMPORTANT: Do NOT match .html here — HTML must stay short-lived so content edits
go live immediately. This rule only targets fingerprinted/versioned static assets.
Verify after ~5 min:  curl -I https://nosh7.in/assets/site.js?v=2026-08-05
  -> should show Cache-Control: max-age=31536000 and cf-cache-status: HIT
--------------------------------------------------
